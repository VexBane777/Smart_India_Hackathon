# VoiceGuard Privileged Call Capture (Magisk module)

## What this is

Real cellular-call audio capture on Android requires the signature-level
`android.permission.CAPTURE_AUDIO_OUTPUT` permission, which the OS only
grants to apps installed as **privileged system apps**
(`/system/priv-app` + an explicit allowlist entry). A normal install —
Play Store, sideloaded APK, `adb install` — can never hold this
permission, no matter what the app declares in its manifest.

This module installs VoiceGuard's `privileged` build flavor
(`android/app/build.gradle.kts`, `android/app/src/privileged/AndroidManifest.xml`)
as a system priv-app on a rooted device, using the same mechanism as the
open-source call recorder [BCR](https://github.com/chenxiaolong/BCR).
Once installed this way, the existing `AudioCaptureManager` source cascade
(`android/app/src/main/kotlin/com/voiceguard/voice_guard/AudioCaptureManager.kt`)
starts succeeding at its first, preferred entry — `VOICE_CALL` — with real,
non-zero-filled downlink audio, instead of falling through to the
acoustic (mic + speakerphone) fallback. **No app capture logic changes**
are needed for this — the cascade already tries `VOICE_CALL` first; it was
only ever unreachable for lack of this permission.

## Who this is for

Rooted-device users only. Everyone else keeps using the normal
`standard`-flavor build with the existing acoustic fallback — that path is
unaffected by any of this.

## Why the privileged flavor can't be pre-built and shipped

- `CAPTURE_AUDIO_OUTPUT` only does anything once the APK is placed under
  `/system/priv-app` with a matching `privapp-permissions` allowlist entry
  (both present in this module). A regular install of the same APK gets
  nothing from declaring the permission — Android silently denies it.
- A priv-app system install and a regular (Play Store / sideloaded)
  install of the same `applicationId` **cannot coexist** on one device.
  Choose one path per device: either install VoiceGuard normally, or
  install it only via this module.
- Because of that mutual exclusivity, this flavor must never be
  distributed through the Play Store or as a normal sideloaded APK — it
  would silently and pointlessly widen every regular user's declared
  permission surface for a permission that does nothing for them.

## Build and install

1. Root the target device (Magisk) if it isn't already.
2. From the repo root: `voice_guard/magisk-privileged-module/build_module.sh`
   — builds the `privileged` flavor release APK and produces
   `voiceguard-privileged-capture.zip` in this directory.
3. If VoiceGuard is currently installed normally on the target device,
   uninstall it first (system + user install can't coexist — see above).
4. Copy the zip to the device, install via Magisk Manager → Modules →
   "Install from storage", then reboot.
5. After reboot, open VoiceGuard and start a real call. Check
   `getCaptureStatus` (or logcat: `"Using audio source: VOICE_CALL"`) to
   confirm the privileged source won, and that `hasRecentSignal` reports
   real (non-zero) signal during the call rather than the
   "Quiet — score paused" state.

## Module contents

- `module.prop` — Magisk module metadata.
- `system/priv-app/VoiceGuard/VoiceGuard.apk` — generated by
  `build_module.sh`; never committed to git.
- `system/etc/permissions/privapp-permissions-com.voiceguard.voice_guard.xml`
  — the allowlist entry that actually grants `CAPTURE_AUDIO_OUTPUT` to a
  priv-app-installed copy of this package.
- `customize.sh` — sets correct file permissions on install and aborts
  with a clear message if the APK is missing (i.e. `build_module.sh`
  wasn't run first).
- `build_module.sh` — builds the `privileged` flavor and assembles the
  zip; the only supported way to produce an installable module.

## Uninstalling / reverting

Remove the module from Magisk Manager and reboot; the system reverts to
its un-modified state (Magisk's overlay is non-destructive). To go back to
a normal VoiceGuard install afterward, uninstall the priv-app copy
(`adb shell pm uninstall --user 0 com.voiceguard.voice_guard` on the booted,
un-modified system, or via Settings) and reinstall the `standard` flavor
normally.
