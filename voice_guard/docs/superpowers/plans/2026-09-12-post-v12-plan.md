## What upstream changed that matters to the model track

1. **Root cause of the on-device failure: the acoustic loop.** A fake that
   scores 0.95–0.99 when read directly scores ~0.01–0.30 once it is played
   through a speaker into a phone mic. Level isn't the cause (-24 dB only
   takes 0.986 to 0.924). Reverb, speaker/mic coloration and room noise
   flatten the cues the model uses. Capture-side DSP fixes were measured
   and made it worse. This is the entity-vs-style confound again
   (`docs/CRITICAL-entity-vs-style-confound.md`).
2. **TeleChannel `playback` recipe:** far room (RT60 600 ms, wet 0.6), pink
   noise at 12 dB, mic clip 0.3, no codec or packet loss, 200–3800 Hz
   passband. `bandlimit.py` gained `low_hz`/`high_hz` overrides and
   `pipeline.py` forwards them. With the overrides unset, the six existing
   recipes produce the same output as before.
3. **`eval_playback_loop.py`:** scores the `test_assets/*.wav` files clean
   and through its own speaker-to-mic simulation, with two gates: fake clean
   score >= 0.60 and fake loop score >= 0.50. The deployed model fails the
   loop gate today (tts_chattts 0.283).
4. **App:** a "Test with audio file" scan (SAF picker, WAV decode, the same
   ONNX path) gives a deterministic on-device check. It changes
   `call_screen.dart`, `audio_service.dart` and `lib/services/src/*`
   (UI-session territory).

## Steps, in order

**1. Let v12 finish and apply the existing decision rule**
(`runs/eval_v12_test/report.md` decision section). v12 is the phone-channel
result. It has never seen `playback`, so it answers "does phone-channel
training beat chance on calls", not "does it survive the acoustic loop".

**2. Merge `origin/vaani` into `voiceguard-v12-hardening` only after stage 3
completes.** `git merge-tree` shows no textual conflicts (tree 3ccd6ee). But
`feature_version()` hashes all of `pipeline.py`, `stages/*.py` and the whole
parsed `channels.yaml`. Merging mid-pipeline would make stage 2/3 raise
`StaleCacheError`. After the merge, every existing unit (98 eval + all
training units, hours of CPU) reads as stale, although none of their
recipes' output changed. That is a false positive of a deliberately
conservative hash, fixed in step 3.

**3. Make cache invalidation precise without making it lax.**
- (a) Recipe-scoped config hash: a unit's version covers only its own
  recipe's parsed block plus the `rooms`/noise presets it references, not
  the whole YAML. Adding a recipe then never invalidates the others.
- (b) `feature_cache.revalidate(unit)`, for code changes:
  1. Re-render a deterministic sample of each stale unit's files under the
     current code.
  2. Compare against the stored `seq`/`scalars` within the fp16 rounding
     tolerance.
  3. If all match, re-stamp the manifest with the new hash and record
     `revalidated_from: <old hash>, sample_n, max_abs_diff`. Otherwise
     rebuild.

  Equivalence is proven by measurement, not assumed.
- Tests: a planted behavior change (for example, shifting the bandlimit
  default by 1 Hz) must fail revalidation; a docstring/new-recipe change
  must pass.

**4. Add `playback` to the protocol as its own channel group, `acoustic`.**
Today `resolve_channels` rejects it ("unknown channel").
- `eval_protocol.ACOUSTIC_CHANNELS = ("playback",)`, included in
  `DEFAULT_EVAL_CHANNELS`. It is not clean audio, so it's compatible with
  the policy.
- evaluate.py reports an `acoustic` row next to seen/unseen phone. The
  headline stays phone-pooled.
- Pre-register the acoustic deploy gate BEFORE scoring any model on it: the
  candidate's playback EER (test, with file bootstrap CI) must beat the
  deployed reference's. Write the gate into EVAL-PROTOCOL.md §6 in the same
  commit.

**5. Bring `eval_playback_loop.py` under the protocol as a supplementary
per-asset gate, not the eval.**
- It uses a handful of assets and its own simulation, which differs from
  the `playback` recipe: RT60 350 ms vs 600 ms, white noise at 15 dB vs
  pink at 12 dB, and 120 Hz HP / 3.8 kHz LP vs a 200–3800 Hz Butterworth.
  It also zero-pads clips under 3 s, where v12 pads with the clip's noise
  floor.
- Keep it as a cheap check of the on-device symptom. The deploy gate also
  requires its `--gate-loop-min 0.50` to pass.
- Close the policy-test hole it exposed:
  `test_every_eval_entry_point_resolves_channels_through_the_policy` checks
  a fixed list of 5 scripts, so a new eval script bypasses it silently.
  Make the test discover every script that parses args and loads a model
  (`load_scoring_model`, `onnxruntime`, `torch.load`). Each such script must
  either call `resolve_channels` or appear in an explicit allowlist with a
  one-line reason. This script's reason: it scores clean and looped
  together, per asset.

**6. Build the playback eval caches.** That's select + test × core, MLAAD
and accents: about 14 units, ~20 min. Then re-score v9, v11 and v12 on the
`acoustic` group. This measures the loop gap on the held-out data, not
just 2 assets.

**7. Train v13: v12's recipe plus playback.**
- Keep v12's `none` + hashed-phone renditions unchanged, so they are
  reusable after step 3.
- Add a third rendition, `playback`, for a hash-selected ~50% of training
  files. Only those new units get built, about half a training-cache
  build.
- Pre-register the selection objective on `select`: EER pooled over phone +
  acoustic channels.
- The confound gates are unchanged.

**8. Deploy decision for v13.** It ships only if it clears all four:
1. every confound gate;
2. the phone headline EER beats the deployed model's;
3. the acoustic-group EER beats the deployed model's;
4. both `eval_playback_loop.py` gates pass.

Then message the UI session before copying to
`assets/models/voice_detector.onnx` (they own `call_screen.dart` and
`lib/services/*`). The attack-type head still has its own gates. If they
fail, hide the sub-label, coordinated with the UI session.

**9. On-device verification.** Put the ONNX through the app's "Test with
audio file" path (deterministic, should match evaluate.py's scores). Then
use Live Mic Test through a real speaker, reading the Logcat `Monitor:
raw=` line. Record both in state.md.
